## История

### 2026-10-25 — диагностика остановившейся синхронизации

- Родитель `https://sync.jacred.stream` не недоступен полностью. С `User-Agent` JacRed `/sync/conf` отвечает HTTP 200 на 172.67.193.89 и 104.21.73.234; без User-Agent тестовый curl получает Cloudflare 403, поэтому не использовать простой curl без прикладного UA как тест доступности.
- Важно исправление предыдущей проверки: повтор `time=134146804057484856` повторяет входной курсор партии `[514]`, а не следующий пакет. Из ответа партии `[514]` получен следующий курсор `134146804062280064`. Запрос этого следующего курсора через `172.67.193.89` с заголовками, близкими к JacRed, вернул корректный JSON: 1 447 коллекций / 2 003 записи, `nextread=true`, примерно за 1,2–1,5 с. Тот же курсор через `104.21.73.234` завис до таймаута 30 с, получено только около 22 КБ неполного JSON. Это подтверждает проблему скорости/полноты ответа через IP 104.21.73.234; закрепление `sync.jacred.stream` за `172.67.193.89` в `/etc/hosts` соответствует результатам теста.
- Текущий API health отвечает HTTP 200. Однако у JacRed PID 3613299 процесс имеет один TCP-сокет к 172.67.193.89:443 в состоянии `CLOSE-WAIT`; других соединений процесса с этими IP во время снимка не найдено. Последняя партия в журнале остаётся `[514]` (2026-10-24 09:39:01), а обычная sync всё ещё без `end` после старта 2026-10-24 10:50:39.
- Проверка источника с точным следующим курсором показывает, что родитель отвечает через закреплённый IP, но это не объясняет само по себе, почему уже работающие задачи JacRed не продолжаются. Владелец сокета `CLOSE-WAIT` — процесс JacRed; большинство потоков ожидают `futex`/служебные события. `strace` с удалённого подключения не запущен: `sudo -n` недоступен, требуется короткий локальный привилегированный снимок syscall, без перезапуска/правок.
- Дополнительный подозрительный, но пока не доказанный фактор: в конфигурации включены `flaresolverr` (`127.0.0.1:8191`) и `cffetch` (`127.0.0.1:8192`), но соединения с этими портами не принимаются. Прямой запрос с правильным UA проходит HTTP 200, поэтому нет доказательств, что именно fallback вызывает остановку; оставить как вторичную проверку.
