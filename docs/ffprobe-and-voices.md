# Проверка ffprobe, voices и languages

## Цель

Проверить четыре разные вещи: поле присутствует в ответе Sync API; сохраняется в локальной FileDB; возвращается локальным API; переживает рестарт. Наличие поля на родителе само по себе не доказывает, что локальная запись содержит то же значение.

## Что следует из upstream-кода

В [SyncController.cs](https://github.com/jacred-fdb/jacred/blob/main/Controllers/SyncController.cs) родительский сервер может добавить потоки из своей TracksDB, если у записи отсутствуют `ffprobe` или `languages`.

В [FileDB.cs](https://github.com/jacred-fdb/jacred/blob/main/Infrastructure/Persistence/FileDB/FileDB.cs) локальная сторона принимает `ffprobe`, если входная запись содержит его, а локальная запись ещё не имеет данных. Поэтому поведение для уже заполненного локального `ffprobe` нужно проверить отдельно: входящее обновление не обязательно перезапишет старое значение.

`voices` присутствует в модели `TorrentDetails`, но [FileDB.Metadata.cs](https://github.com/jacred-fdb/jacred/blob/main/Infrastructure/Persistence/FileDB/FileDB.Metadata.cs) вызывает `updateFullDetails()`, пересчитывающую качество, видеотип, голоса и языки. Голоса определяются по названию релиза, трекеру и названиям аудиодорожек в `ffprobe` или локальной TracksDB. Поэтому `voices` и `languages` нельзя считать гарантированно скопированными с родителя без изменений.

## План эксперимента

Выбрать минимум три записи по стабильному идентификатору (infohash/magnet):
1. у родителя есть `ffprobe` и названия аудиодорожек;
2. голоса определяются из заголовка релиза, но потоки отсутствуют;
3. локальная запись уже имеет `ffprobe`, чтобы проверить обновление.

Для каждой записи сравнить:

| Поле | Проверка |
|---|---|
| Идентификатор | Одна и та же раздача |
| `ffprobe` | Наличие, тип потока, кодек, язык и `tags.title` |
| `voices` | Список голосов на родителе и локально |
| `languages` | Значения вроде `rus` / `ukr` и основания для них |
| Персистентность | Результат после рестарта |

Затем, после первичной синхронизации, включить `tracks=true` и отдельно проверить локальный анализ одной контролируемой раздачи. По журналу и состоянию записи определить, какие данные пришли от родителя, а какие рассчитаны локально.

- [ ] Подтверждена передача `ffprobe`.
- [ ] Подтверждено сохранение и чтение после рестарта.
- [ ] Определено, когда пересчитываются `voices` и `languages`.
- [ ] Проверено обновление уже заполненного `ffprobe`.
- [ ] Записаны расхождения и решение о необходимости доработки.

До окончания проверки проект не заявляет, что метаданные синхронизируются без потерь.
